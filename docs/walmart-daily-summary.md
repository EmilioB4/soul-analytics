# Walmart daily summary
After deploying, run supabase/walmart_daily_summary.sql in the SAME Supabase project configured for this website. This is separate from the sale-alert migration; it can be rerun. Keep CRON_SECRET (16+ characters), TIKTOK_TOKEN_ENCRYPTION_KEY, the Supabase URL/service key, and PAYOUT_APP_URL configured for this Vercel project. Existing encryption keys must not be replaced.

Open Webhooks in the sidebar. Connect your own Walmart account in Integrations first. Under Walmart daily summary, enable the summary and either reuse your saved sale-alert webhook or supply a separate Discord URL. Save daily summary installs the minute scheduler and queues the first background request. No manual Check now is required. Supabase pg_cron/pg_net/Vault runs with the browser closed. The scheduler URL is bound to the deployment's trusted configured origin; separate Supabase projects need separate installation.

The worker considers the current New York day due at 23:59; before then it checks the preceding day for retry/catchup. Enabling starts with today's report, without replaying historical days. DST follows America/New_York rather than a fixed UTC offset. Three accounts are serviced per minute, in least-recently-checked order; larger queues or provider failures may delay delivery beyond 23:59. If the service is unavailable for over a day, older reports are not backfilled automatically.

Each report freshly imports that day's Walmart orders, then uses the dashboard's fee allocation, refund deduplication, saved COGS, returned-cost credits and expected fee model. Revenue includes recorded shipping less known refunds; units sold are original sale quantities, and orders are distinct purchase orders. Profit is estimated and excludes unrecorded outside expenses and the separate optional cushion. Required unavailable financial sources or missing SKU costs make profit Unavailable. Revenue is labelled provisional when data is partial.

A report sent at 23:59 is a snapshot, not a finalized full-day settlement. It can omit the final minute, delayed orders, subsequent refunds and fees. Import sync does not itself fetch settlement reports. No product images, buyer details, bank data, API credentials or webhook tokens are sent. Mentions are disabled.

Preferences, report history, delivery leases and Vault scheduler configuration are server-only. Session APIs derive the owner; the internal importer requires CRON_SECRET plus an active owner/day lease. Reusing a sale webhook resolves its current saved value at delivery, so replacements are followed. A unique owner/day key prevents routine duplicates. Interrupted ambiguous sends become uncertain and are not resent automatically; rate limits and pre-send source failures retry. Check the Webhooks history and the Discord channel for uncertain delivery.

Validation commands: node scripts/validate-walmart-daily-summary.cjs; node scripts/validate-walmart-daily-sql.cjs; npm run test:isolation; npm run test:sale-alerts; npm run build. SQL tests stub scheduler/network/Vault APIs in local PGlite; they do not send Discord messages or exercise hosted services.
